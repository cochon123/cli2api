Architecture plan · local-only · open source

CLI → AI API

A Clerk-like drop-in for local agent CLIs: expose Claude Code, Codex, OpenCode, and friends as an OpenAI-compatible HTTP API on localhost — so any app can swap one env value and keep using the model you already pay for / authenticate via CLI.

1. The pitch

Auth products won by being boring infrastructure: one SDK, one env, works everywhere. Coding CLIs already own the hard parts — login, quotas, model routing, tool loops — but they speak terminal, not HTTP.

This project is the missing adapter layer: a tiny local gateway that speaks the API shape every LLM client already knows, and translates each request into the right CLI invocation (or local SDK) for the backend you choose.

North star

OPENAI_BASE_URL=http://127.0.0.1:3927/v1 — and your benchmark, eval harness, or side project suddenly runs on whatever CLI is installed on this machine. No cloud proxy. No shared multi-tenant service.

Audience

Personal daily driver and open-source for others. Defaults must be safe for a stranger who clones the repo and runs serve with no extra flags — not just for the author who already knows the threat model.

2. Hard scope (local only)

In scope

Bind to loopback only (no override). Single-user machine. Required local bearer token (auto-generate if unset). Read-only agent sandbox by default. Pluggable backends for CLIs you run yourself. OpenAI-compatible chat + models. Streaming. Clear docs + Cursor skill + CLI. MIT open source.

Out of scope

Public SaaS, multi-tenant hosting, exposing your CLI auth to the internet, open CORS for arbitrary browser tabs, reverse-engineering paid APIs for redistribution, or anything that looks like “rent out Anthropic/OpenAI via someone else’s subscription.”

Legal / ToS posture

Ship as a local developer tool (personal use + open source). Document that users must comply with each CLI vendor’s terms. Default bind 127.0.0.1 only — refuse non-loopback binds with no escape hatch. No “deploy this as a shared API” docs.

3. Killer use case: one env swap

You already have a benchmark with a working OpenAI-shaped client. You don’t want to rewrite the harness — you want the harness to call your CLI.

Before · cloud API
OPENAI_API_KEY=sk-...
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4.1
→ swap →
After · local CLI gateway
OPENAI_API_KEY=<token from serve>
OPENAI_BASE_URL=http://127.0.0.1:3927/v1
OPENAI_MODEL=codex/default
# terminal A — start the gateway once (prints token if unset)
npx cli2api serve --adapter codex --port 3927

# terminal B — run your existing benchmark with the printed token as OPENAI_API_KEY
npm run bench
What the numbers actually mean

A CLI adapter is an agent loop (tools, repo context, timeouts, sandbox) wearing a model id — not a raw completion endpoint. Benchmarks that compare gpt-4.1 cloud vs codex/default are comparing a model to an agent-with-guardrails. Document that honestly in the capability matrix; don’t pretend the base-URL swap makes them equivalent experiments.

4. Architecture

Three layers: a thin HTTP façade, a normalizer that maps OpenAI request/response shapes, and adapters that know how to talk to each CLI.

Core components

01

HTTP server

Fast local server (Node). Loopback bind only. Required bearer token. No open CORS. Request logging for debug.

02

Protocol layer

Parse OpenAI chat payloads, emit OpenAI responses + SSE chunks. Prefer an event union that keeps tool/agent events distinct even before full function-calling parity.

03

Adapter registry

Discover adapters by name. Each implements listModels, chat, optional stream.

04

Process manager

Spawn via fixed argv arrays (shell: false). Timeouts, concurrency limits, cwd sandbox, env scrubbing (planned), cancel on client disconnect.

05

Config

~/.config/cli2api/ + project config. Model aliases, default adapter, ports, pinned token.

06

Observability

Local request log, latency, token estimates when available, adapter stderr capture for failures.

5. API surface (compatibility first)

Don’t invent a new protocol. Implement the subset that makes 90% of clients work with zero code changes.

Endpoint Priority Notes
POST /v1/chat/completions P0 Non-stream + stream: true SSE. Map messages → CLI prompt.
GET /v1/models P0 Return adapter-prefixed ids: claude-code/sonnet.
POST /v1/responses P1 Newer OpenAI Responses API — add when clients need it.
POST /v1/embeddings P2 Only if an adapter can provide it; otherwise 501 with clear error.
GET /health P0 Adapter ready? CLI binary found? Auth ok?

Model ID convention

adapter/model           # claude-code/sonnet
adapter/alias           # codex/default
alias                   # from config: "bench" → claude-code/opus
Honest capability matrix

CLIs are not full chat APIs — and they are not raw models either. Document per-adapter: streaming quality, multi-turn fidelity, tool/function calling, vision, system prompt support, max context, and whether the backend is agent-mode (tools + repo) vs completion-mode. Prefer clear 501/422 over silent degradation.

6. Adapter strategy

Each CLI is different. Some have headless / print modes; some need TTY tricks; some expose a local SDK. Start with the easiest reliable path per tool, then improve.

Adapter Likely approach MVP difficulty
Codex CLI codex exec --json; argv spawn; default -s read-only Done (P0)
Claude Code Headless -p --output-format stream-json; plan mode; built-in + MCP tools disabled Implemented (not live-tested: CLI unavailable)
OpenCode run --format json --thinking; read-only “plan” agent; external plugins disabled Done
Cursor Agent -p --output-format stream-json --stream-partial-output; ask mode + sandbox Done
Generic shell Deferred / discouraged. Template + {{prompt}} is the textbook injection shape. Prefer first-class adapters. Avoid for MVP
Mock Deterministic replies for CI of the gateway itself Done (P0)

Adapter interface (sketch)

type ChatEvent =
  | { type: "delta"; text: string; channel?: "content" | "reasoning" }
  | { type: "tool.started"; name: string; id?: string }   // keep even if OpenAI tools deferred
  | { type: "tool.completed"; name: string; id?: string }
  | { type: "done"; finishReason: "stop" | "length" | "error"; usage?: Usage }
  | { type: "error"; message: string; code?: string }

interface Adapter {
  id: string
  listModels(): Promise<ModelInfo[]>
  chat(req: NormalizedChatRequest, signal: AbortSignal): AsyncIterable<ChatEvent>
  health(): Promise<HealthStatus>
}
Adapter sequencing

Prove one adapter (Codex) end-to-end before going wide. Add Claude Code / OpenCode only once they pass the same contract suite. Do not ship a generic shell-template adapter to fake multi-backend breadth.

Keep adapters in-repo first (adapters/codex, …). Later: load external adapters from a path for power users — still local, still not a marketplace for piracy.

7. Agent-friendly DX

If agents can’t install and wire this in one shot, it fails the Clerk test. Ship three surfaces that all say the same thing.

CLI

cli2api

serve, adapters, doctor, models, completion (smoke test). Machine-readable --json everywhere.

Docs

Short + copy-paste

One README “30-second start”, per-adapter pages, capability matrix, env cheat sheet for OpenAI / Anthropic / litellm clients. Explicit “not yet” list (env scrubbing, etc.).

Skill

Cursor / agent skill

SKILL.md: when to use, how to start server, which env vars to set, how to debug doctor, never bind public interfaces, always use the printed token. Paths relative to project root — never hardcode one machine.

What an agent should be able to do unaided

  1. Detect installed CLIs via cli2api doctor
  2. Start gateway on a free port and capture the printed token
  3. Patch the user’s .env with base URL + token + model id
  4. Run a one-shot smoke completion
  5. Explain adapter limitations if the bench needs tools/vision
# agent-friendly smoke
cli2api doctor --json
cli2api serve --adapter codex --port 3927 &
cli2api completion --model codex/default -p "ping"

9. Risks & design decisions

CLI ≠ chat API

Agent CLIs may inject system behavior, tools, or repo context. Decide: “raw completion mode” vs “agent mode.” Expose as model variants or request flags. Benchmark numbers against a cloud model API are not apples-to-apples.

Streaming fidelity

Many CLIs only emit final stdout. Start with fake-stream (chunk the final answer) then upgrade adapters that support true token streams.

Auth & secrets

Never scrape cloud API keys from CLI configs to call vendor HTTP APIs directly unless the user explicitly opts into a documented “use my key” path. Prefer invoking the CLI as the user does.

Concurrency

CLIs often assume one interactive session. Default concurrency=1 per adapter; queue or reject with 429. Document rate limits honestly.

Headless = no human approver

Interactive CLIs ask a human before risky tools. Headless mode moves that job into flags. Default every adapter to the CLI’s most restrictive mode (Codex read-only, Claude allowlist/locked, OpenCode plan). Writes/network are named opt-in profiles only.

Vendor breakage

CLI flags change. Version-pin adapters, run doctor probes, and keep a compatibility table in docs.

Non-goal reminder

Do not build a hosted “bring your Claude Max, we expose an API to the world” product. That is the illegal / ToS-hostile version of this idea. The product is a local developer tool, like a reverse proxy for your own laptop — open-sourced so others can run the same pattern on their machines.

10. Security non-negotiables (open source)

Loopback binding alone is not enough. Same-machine browser tabs can still hit 127.0.0.1. Read-only sandbox stops disk writes; it does not stop the agent from reading files and returning their contents. Defaults must close both the “who can talk to the gateway” and “what the agent may do” paths.

Control Rule Status
Bind Loopback only (127.0.0.1 / ::1). Refuse other hosts — no override flag. Done
Auth Bearer token required on every request. Auto-generate + print to stderr if unset. Done
CORS No CORS middleware by default. SDK/script clients don’t need it. If a local UI is added later, pin an explicit origin allowlist. Done
Spawn Fixed argv arrays only — never shell: true, never concatenate prompts into a shell string. Resolve binaries via which argv, not sh -c. Done
Agent permissions Default each adapter to the CLI’s most restrictive mode (Codex read-only). Opt-in profiles for write/network. Done (Codex)
Env scrubbing Don’t pass the full parent env to children forever. Document as not-yet until implemented. Not yet
Generic shell adapter Do not ship a {{prompt}} command template as the multi-adapter escape hatch. Deferred
License MIT in package.json and a real LICENSE file. Done
Read-only ≠ private

A malicious page that can call the gateway can still ask the agent to read and print secrets. Token + no CORS close that path for browser JS. Keep treating “who can call me” as a first-class control, not an afterthought to sandbox mode.

11. Naming & next step

Shipped name: cli2api (github.com/cochon123/cli2api). Earlier working names: cligateway, agentport, loopback-llm.

Suggested next move

Phase 0 is done and P1 now includes Codex, OpenCode, Cursor Agent, and Claude Code, scrubbed child environments, JSON config/model aliases, function-call shaping, a Responses API subset, and native session resume. Next: concurrency hardening and the remaining P2–P3 polish.

Success criteria for Phase 0

  • Gateway starts in <1s on localhost
  • OpenAI Python/JS SDK completes a chat with only base URL + API key changed
  • Your real benchmark runs end-to-end against the CLI adapter
  • Failure modes are readable (missing binary, not logged in, timeout)
  • Unauthenticated requests fail; non-loopback bind refused; Codex defaults read-only

12. Lessons learned

Non-trivial findings from building Codex streaming + wiring Scrabble Bench. Keep these in mind for the next adapter / streaming work — don’t rediscover them.

Codex exec --json is item-level, not token-level

  • The JSONL stream emits lifecycle + completed items (thread.started, turn.started, item.completed, turn.completed), not per-token deltas.
  • The assistant answer arrives as one item.completed with item.type: "agent_message" (full text). Fake-stream that blob word-by-word if clients need a typing effect.
  • HTTP SSE can still be “real” (line-by-line as events arrive). The gap is the CLI protocol, not the gateway transport.

Session fidelity belongs at the adapter boundary

  • Each CLI uses a different resume flag and emits its native session id in a different JSON event.
  • Keep API response ids separate from native ids, map them in memory, and bind every mapping to its adapter.
  • When a native transcript is resumed, send only the new tail after the last assistant turn; replaying the full history duplicates context.

Tool compatibility needs an explicit fallback contract

  • The CLIs do not share a callable tool-event protocol, so function schemas are supplied in the prompt using a strict JSON envelope.
  • Buffer only assistant content for tool-capable turns; keep reasoning and session events live, then validate names, JSON argument objects, and strict JSON Schemas before emitting API tool calls.
  • Responses streaming is semantic: emit lifecycle, output-text, and function-argument event types rather than wrapping Chat Completions chunks.

Reasoning effort ≠ reasoning on the wire

  • model_reasoning_effort only controls how hard the model thinks. By default, reasoning summaries are off (model_reasoning_summary = none).
  • To get item.type: "reasoning" on JSONL, pass explicitly: -c model_reasoning_summary=detailed, -c model_supports_reasoning_summaries=true, -c hide_agent_reasoning=false.
  • Trivial prompts may still skip a reasoning item; harder prompts + detailed is what surfaces summaries.
  • Summary text is a short block (sometimes with empty <!-- --> markers) — treat it like content: fake-stream word-by-word into a reasoning channel (delta.reasoning / OpenRouter-style).

Don’t confuse status with reasoning

  • Heartbeats (“waiting for Codex…”), stderr (MCP auth failures, stdin notices), and lifecycle crumbs are useful for ops — but dumping all of them into the reasoning panel looks like “thinking” and can spam thousands of chars.
  • Prefer: real reasoning items → fake-streamed reasoning channel; short activity crumbs optional; never mirror idle heartbeats 1:1 into UI reasoning.

Process / stdin gotchas

  • Codex hangs with Reading additional input from stdin... if stdin stays open. Always close stdin (DEVNULL / end the pipe) for non-interactive exec.
  • Buffer-until-exit kills time-to-first-token. Stream stdout line-by-line (JSONL) even when you still fake-chunk the final message.
  • Abort must kill the child (SIGTERM → SIGKILL). Client disconnect should not leave orphaned codex processes.
  • Killing only the top-level CLI is insufficient when helpers inherit its pipes. Spawn a dedicated process group and terminate the group so timeouts actually close the JSONL iterator.

OpenCode JSON is block-level; Cursor is genuinely partial

  • OpenCode run --format json --thinking emits completed reasoning and text parts, followed by a step_finish carrying usage. Fake-stream those completed blocks.
  • Cursor Agent with --stream-partial-output emits native thinking deltas and partial assistant text, then repeats the full assistant message. Keep partial deltas and suppress the duplicate full block.
  • A tiny completion can succeed while an agent model stalls on a full benchmark prompt. Contract probes and realistic one-board tests catch different failures.

Claude can be implemented safely without pretending it was tested

  • The official headless contract supports -p, --output-format stream-json, and --include-partial-messages (with verbose output).
  • Default the unattended adapter to --permission-mode plan, disable built-in tools with an empty --tools value, and exclude configured MCP tools. Keep the adapter marked unverified until a real installed CLI passes.

Environment scrubbing needs an escape hatch, not full inheritance

  • Preserve only normal process/runtime paths, locale, home/XDG locations, and the narrow auth/config variables each adapter actually needs.
  • Unrelated application secrets must not reach spawned agents. Exceptional keys are explicit via CLI2API_CHILD_ENV_ALLOWLIST.

Protocol / client compatibility

  • OpenRouter-shaped clients expect reasoning on delta.reasoning (sometimes also reasoning_content). Emit both when bridging.
  • Non-stream collectors should keep content only — don’t fold reasoning crumbs into the final assistant message.
  • Benchmark UIs that talk to Codex directly won’t see cli2api SSE improvements until they use the gateway or mirror the same JSONL → channel mapping.

Adapter checklist (next CLI)

  1. What does the CLI actually emit under “JSON/stream” mode? Capture a sample.
  2. Is there a separate flag for summaries / traces vs effort / temperature?
  3. Map: lifecycle → optional status; model thought → reasoning; final answer → content.
  4. If blobs not tokens: fake-stream words; document honesty in the capability matrix.
  5. Close stdin; stream lines; kill on abort; use the scrubbed env helper.
For the next implementation

Before claiming “streaming” or “reasoning” for a new adapter, verify with a raw CLI capture that the events exist, then wire flags that unlock them. Update this section when you learn something non-obvious.
